# 📖 典型用法示例

> 本文件是 `personal-memo` 技能的配套示例：覆盖完整多阶段、批量导入、完成闭环、播报、周报、周期任务等典型场景。规则以 `SKILL.md` 为准。

---

## 1️⃣ 记一条重要任务（完整多阶段示例）

**用户**：帮我记一下，10月20日18:00前必须交项目周报给客户

**① 自动分级**：含"必须…给客户" → 识别为 🔴 **重要**（回复时明示，用户可改级）。

**② 创建飞书待办**：

```bash
lark-cli task +create --summary "交项目周报给客户" --assignee "ou_2b934d4428a22adfc9e45ccd21e4c15c" --due "2026-10-20T18:00:00+08:00" --description "级别：重要"
```

假设返回 `guid=xxx`、`url=yyy`。

**③ 按时刻表创建 6 个 at 定时任务**（截止 2026-10-20 18:00；title 统一无空格）：

| title | at 触发时间（截止前） |
|---|---|
| 交周报-重要-提前1天 | 2026-10-19 18:00 |
| 交周报-重要-提前12小时 | 2026-10-20 06:00 |
| 交周报-重要-提前4小时 | 2026-10-20 14:00 |
| 交周报-重要-提前1小时 | 2026-10-20 17:00 |
| 交周报-重要-提前30分钟 | 2026-10-20 17:30 |
| 交周报-重要-最终检查 | 2026-10-20 17:59 |

**阶段提醒 query**（以"提前1小时"为例；第 1 步查任务状态、第 2 步深夜静默、第 5 步失败重试）：

```text
本次请求是由「交周报-重要-提前1小时」定时任务到时触发的。请执行以下动作：
1. 用 lark-cli 查询飞书任务 xxx（url yyy）的当前状态；若任务已完成/已结束，本次不发送任何消息，直接结束。
2. 若当前时间处于 23:00–07:00 且该任务级别非「重要」，跳过本次发送，在回复中说明"深夜静默已跳过"，直接结束。
3. 读取文件 /Users/mima1234/DoubaoWork/feishu-reminder-webhook.txt 中的飞书自定义机器人 Webhook 地址（去除首尾空白）。
4. 用 curl 以 POST JSON 方式向该地址发送提醒消息，内容如下：
{"msg_type":"text","content":{"text":"📌 待办提醒：交项目周报给客户\n🔥 级别：重要\n⏰ 截止时间：2026-10-20 18:00（还剩1小时）\n🔗 任务链接：yyy"}}
5. 若发送失败（HTTP 失败或响应 code 不为 0），等待约 10 秒后重试一次；仍失败则在回复中明确说明失败原因，不要静默跳过。
```

**最终检查 query**（不受深夜静默限制，深夜截止也会推）：

```text
本次请求是由「交周报-重要-最终检查」定时任务到时触发的。请执行以下动作：
1. 用 lark-cli 查询飞书任务 xxx（任务链接 yyy）的当前状态。
2. 若该任务已完成/已结束，本次不发送任何消息，直接结束。
3. 若任务仍未完成，读取文件 /Users/mima1234/DoubaoWork/feishu-reminder-webhook.txt 中的飞书自定义机器人 Webhook 地址（去除首尾空白），用 curl POST 推送最终提醒：
{"msg_type":"text","content":{"text":"⏰ 最终提醒：交项目周报给客户 将在 1 分钟内到期，若还未完成请抓紧处理\n🔗 任务链接：yyy"}}
4. 若发送失败（HTTP 失败或响应 code 不为 0），等待约 10 秒后重试一次；仍失败则在回复中明确说明失败原因，不要静默跳过。
```

**💡 时间过近跳过**：如果用户当天 16:00 才创建截止 18:00 的重要任务，则"提前1天/12小时/4小时"三个提醒点已过期，只创建"提前1小时(17:00)、提前30分钟(17:30)、最终检查(17:59)"，并告知跳过的阶段。

**💡 深夜静默**：任务截止 07:59、级别「正常」，其"提前1小时"阶段提醒点原本落在 06:59 → 落入静默区间（23:00–06:59），平移到当日 07:00 推送。重要级别不调整；最终检查不受静默限制。

## 2️⃣ 批量导入

**用户**：帮我记三件事：周一上午10点交采购清单（重要）；周三下午2点见客户；周五下班前把桌面整理一下（不紧急）

- 逐条解析并各走完整流程：3 个飞书待办 + 对应阶段提醒（重要 5+1 点、正常 1+1 点、不紧急 1+1 点）。
- 回复汇总表：任务 / 级别 / 截止 / 提醒点数量 / 任务链接。
- 某条缺截止时间时：一次列出所有缺失项向用户确认，不逐条打断。

## 3️⃣ 完成确认闭环

**场景**：用户在「代办提醒」群收到提醒后，回复「完成了」或「交周报完成」。

- 「完成确认扫描」（每小时）读取游标文件 `feishu-reminder-scan-cursor.txt`，只处理上次扫描之后的新消息 → `lark-cli task +complete` 勾选对应飞书任务 → 删除标题以「交周报-」开头的剩余阶段提醒 → **全部处理完成后再更新游标**。
- 匹配规则：带任务名的回复（「交周报完成」）最可靠；裸「完成」匹配游标窗口内其上方最近一条提醒对应的任务（提醒带任务链接）；「每日任务播报」「完成确认扫描」「每周任务回顾」三个常驻任务永不删除。
- 双保险：后续阶段提醒即使未删，触发时也会先查任务状态，已完成则静默不推。
- 用户也可以直接在对话里说「交周报完成了」，立即处理。

## 4️⃣ 每日任务播报（常驻）

每天 08:00 自动推送，示例输出：

```text
📅 今日待办（10月20日）
今日截止：
1. 交项目周报给客户（18:00，重要）
2. 下午2点见客户（14:00，正常）
已逾期：
1. 整理桌面（原截止 10-18，不紧急）
```

- 无截止写「今日暂无待办」；无逾期写「无逾期」；最多列 10 条；旧任务无级别标注时省略级别。
- 播报时间可调：「把播报改到早上7点半」。

## 5️⃣ 每周任务回顾（常驻）

每周日 20:00 自动推送。**统计口径**：任务范围 = 截止时间落在本周（周一 00:00–周日 23:59）的任务；已完成数 = 范围内已标记完成的任务；逾期数 = 已过截止仍未完成、或完成时间晚于截止的任务。示例输出：

```text
📊 本周任务回顾（10月14日~10月20日）
完成：5/8（63%）
逾期：2 个
按级别：重要 3 / 正常 3 / 不紧急 2

建议：本周逾期偏多，下周重要任务建议提前规划。
```

## 6️⃣ 周期任务（含 query 模板）

**用户**：每个工作日早上9点半提醒我规划当天任务（正常级）

- `cron` 工作日表达式（如 `30 9 * * 1-5`），不套多阶段时刻表。
- query 示例：

```text
本次请求是由「每日规划提醒-正常-周期」定时任务到时触发的。请执行以下动作：
1. 若当前时间处于 23:00–07:00 且该任务级别非「重要」，跳过本次发送，在回复中说明"深夜静默已跳过"，直接结束。
2. 读取文件 /Users/mima1234/DoubaoWork/feishu-reminder-webhook.txt 中的飞书自定义机器人 Webhook 地址（去除首尾空白）。
3. 用 curl 以 POST JSON 方式向该地址发送提醒消息，内容如下：
{"msg_type":"text","content":{"text":"📌 待办提醒：规划当天任务\n🔥 级别：正常\n⏰ 每工作日 09:30"}}
4. 若发送失败（HTTP 失败或响应 code 不为 0），等待约 10 秒后重试一次；仍失败则在回复中明确说明失败原因，不要静默跳过。
```

## 7️⃣ 重复任务模板

**场景**：用户这个月第二次说「周五下班前交周报」 → 主动提示：「要不要转成周期任务模板，以后每周五 18:00 自动提醒交周报？」用户确认后按周期任务创建。判定依据：去除日期前缀（周五/明天/10月20日等）后任务名相同即视为重复。

## 8️⃣ 大任务拆解

**用户**：帮我准备下周的发布会，周五前完成

- 识别为重要 + 多步骤 → 主任务「准备发布会」（due 周五）→ 拆子任务：「写演讲稿（周三）」「做PPT（周四）」「彩排（周五上午）」。
- 子任务挂到主任务下（+set-ancestor），各自建飞书待办与提醒（默认正常级：提前1小时）；主任务按重要级建 5+1 点提醒。

## 9️⃣ 提醒节奏配置化

**用户**：重要任务的提醒改成提前3天、1天、6小时、1小时

- 更新默认时刻表：以后的重要任务按新表执行；**同步更新 SKILL.md 的"默认时刻表"段落**；已建的重要任务删旧建新（只重建尚未触发的点）。
- 单任务覆盖：用户说"这条任务只提前10分钟提醒一次" → 该任务仅建 1 个提醒点。

## 🔟 正常任务 / 不紧急任务

- 🟡 正常：「下午3点开会」→ 飞书待办（due 15:00）+ 提前1小时 at 任务。
- 🟢 不紧急：「有空的时候看看那篇文章」→ 飞书待办 + 提前30分钟 at 任务；无明确时间时先确认截止时间。

## 改级 / 改内容 / 查看 / 暂停 / 删除

- **改级**（如把「交周报」从正常改为重要）：先 `task +update` 更新飞书任务 description 的级别为「重要」→ 再删除该任务尚未触发的阶段点 → 按重要时刻表重建。保证播报/周报读到新级别。
- **改内容**：`task +update` 更新飞书任务 summary/description → 按新内容重建阶段提醒。
- **查看**：飞书任务中心；提醒计划用 `list_cron_jobs`，按任务分组展示。
- **改时间/改节奏**：先定位该任务全部 at 任务（标题「任务名-」前缀），删除尚未触发的点，再按新时刻表重建；不用 `update_cron_job` 改阶段点。
- **暂停/恢复/删除**：按任务分组操作 `update_cron_job`（enable）/ `delete_cron_job`；删除前与用户确认。

## 时间有歧义时先澄清

用户在凌晨说"明天早上9点提醒我" → 给出候选：今天 09:00（几小时后）还是明天 09:00（自然日明天），写成明确日期+星期+时间，待用户确认后再创建。
